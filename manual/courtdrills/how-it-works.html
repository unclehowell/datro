Manual · Court Drills · How it works

How Court Drills is built, deployed and fed.

At a glance

Branchcourtdrills (datro)
Build and deploy pathwork/courtdrills/build.py writes public/index.html and public/data/register.json from one points file → datro@courtdrills → Cloudflare Pages project bucklerfamily-courtdrills (output public/, no build step)
Live addresshttps://courtdrills.bucklerfamily.estate/
Source of truth it ownsThe court-drills register (data/register.json).
What it readsThe BAILII text of [1987] EWCA Civ 2; HM Land Registry, Strasbourg, Cadw and Welsh Government records linked from Wayback.
Sites it reads fromThe Wayback Vault, The Grammar House (CSSCPSGP), The Legal Wiki
Sites that read from it—
Data flow

Every point is one record in data/register.json: id (P = procedural unfairness, M = court mistakes, O = other miscarriages of justice), date, forum, proc (the stage of the proceedings it sits under), t (the line), what, quote, why, basis (record or family’s case) and src[]. The page embeds the same records, so the line, the popup and the JSON never disagree.

Artifacts are linked from Wayback and open in the shared artifact viewer; no copy is kept on this site (single-source rule).

Design system (frozen)

Plain monospace, one line per point, red for highlighted lines, a popup for detail, as on the Grammar House. Toggles: ?h=p (default), ?h=m, ?h=o or any mix; #P04 opens a point. Pages start directly under the shared header.

Deploy and verify

Branch: courtdrills
Route to live: datro@courtdrills → Pages bucklerfamily-courtdrills → courtdrills.bucklerfamily.estate

Then verify live at 390 px and 1280 px as in deploy and verify: header shows, the three toggles change the red lines, no sideways scroll, a popup opens with its sources.

Shared layer

  • Header and tour bar: ghf-boot.js?v=2.1.4, the last element in <head>.
  • Artifact viewer: wayback.bucklerfamily.estate/viewer/ghf-viewer.js.
