# Brief: Email correspondence catalogue page for one institution — Great House Farm wiki

Context: Hywel/Sion Buckler (Gmail account hywelapbuckler@gmail.com, signs emails "Sion Buckler") runs a public evidence-catalogue wiki at greathousefarmwiki.wordpress.com about Great House Farm (Tŷ Mawr), Llandough, and the Williams/Buckler family's dispossession (BP Properties v Buckler 1987, demolition 1988). He wants every email thread with each institution about the Williams family or the farm published on the wiki, word for word, one page per institution, linked from that institution's existing "Forensic Institutional Review" page. He has explicitly approved publishing (status "publish") and asked for NOTHING to be redacted (phone numbers, names, addresses all stay as written). He wants pages worded in the family's favour, but these catalogue pages are transcripts — do not add commentary beyond a one-line factual note where needed.

## Tools
- Gmail: load via ToolSearch `select:mcp__Gmail__search_threads,mcp__Gmail__get_thread`. Use get_thread with messageFormat PLAIN_TEXT.
- WordPress: load via ToolSearch `select:mcp__WordPress_com__wpcom-mcp-content-authoring`. Site: greathousefarmwiki.wordpress.com. Every create/update needs `"user_confirmed": true` in params (already approved by the user).

## Steps
1. Find threads: search Gmail with your institution's domain(s) (e.g. `from:DOMAIN OR to:DOMAIN OR cc:DOMAIN`, pageSize 50, page through nextPageToken) plus keyword searches (reference numbers, institution name). Keep only threads about Great House Farm / Tŷ Mawr / Llandough / the Williams or Buckler family / the BP v Buckler case / related FOI, EIR, SAR, complaint or records requests. Include WhatDoTheyKnow notification emails only as a pointer (title, date, link to the public request page). Exclude unrelated mail and the "foi-inbound-triage" noreply@x.ai automation emails.
2. Fetch each thread in full with get_thread (search results show at most 5 messages per thread). Transcribe EVERY message as its own entry. Strip only the quoted earlier messages ("On ... wrote:", "From: ... Sent: ..." blocks), Outlook banners ("You don't often get email from…", "This email comes from outside the organisation…"), and image placeholders like [cid:...] / logo descriptions. Keep everything else verbatim, including spelling errors, signatures, phone numbers, reference numbers. If an original email only survives in quoted text (e.g. a request sent from another account), add it as its own entry with a note "recovered from the quoted text of the reply of <date>". List attachments by filename.
3. Save entries to /home/claude/corr/<SLUG>_N.json as a list of objects: {"thread": short thread title (e.g. "FOI 1040/26 — 1988 operational records"), "date": "YYYY-MM-DDTHH:MM:SSZ" (UTC from Gmail), "from": display name/role (use "Sion Buckler" for the family), "to": recipients, "subject": subject, "body": verbatim text with "\n\n" between paragraphs, optional "attachments", optional "note"}.
4. Build HTML: write a config /home/claude/corr/<SLUG>.cfg.json like
   {"prefix":"<SLUG>","name":"<Full institution name>","short":"<short name>","out":"corr/<SLUG>.html","forensic_url":"<relative path of forensic page>","forensic_title":"<its title>","pending":[]}
   then run `cd /home/claude && python3 corr/build.py corr/<SLUG>.cfg.json`. (build.py already exists; do not modify it. If it is missing, ask the parent.) Leave "pending" empty unless a thread genuinely could not be fetched — then list it there.
5. Publish: mcp__WordPress_com__wpcom-mcp-content-authoring, action execute, operation pages.create, params {"title":"<Institution> — Email Correspondence Catalogue","status":"publish","parent":1097,"excerpt":"Every email between the Williams/Buckler family and <Institution> about Great House Farm, word for word, by thread and date.","content": <the HTML file contents exactly>,"user_confirmed":true}. Before creating, run pages.list with search "<Institution> — Email Correspondence Catalogue" (status publish/draft) to avoid duplicates; if one exists, use pages.update on it instead. If the page is very large (>150k chars), split into Part 1 / Part 2 pages by thread, each linking the other.
6. Link from the forensic page(s): for each forensic page id given, call page-sections.list (params {"id":ID}) to get modified + content_hash, then page-sections.insert with {"id":ID,"index":0,"expected_block_type":"core/paragraph","expected_modified":...,"expected_content_hash":...,"user_confirmed":true,"block_markup":"<!-- wp:paragraph -->\n<p><strong>Email dialogue evidence:</strong> every email exchanged with <Institution> about Great House Farm is catalogued word for word, by thread and date, at <a href=\"<published link>\"><Institution> — Email Correspondence Catalogue</a>.</p>\n<!-- /wp:paragraph -->"}. If the page has no blocks and the insert fails, fall back to pages.get + pages.update prepending that paragraph to the existing content unchanged.
7. Verify: pages.get the new page (include_fields id, link, title) and confirm the forensic page now starts with the link. Check `_content_warnings` on writes.
8. Report back in under 150 words: published page link + id, number of threads and emails, forensic page(s) linked, any threads that could not be fetched or anything ambiguous (e.g. multi-authority emails you put on this page).

Do not send, reply to, label or modify any email. Do not edit any wiki page other than the new catalogue page(s) and the named forensic page(s).
