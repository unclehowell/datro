Quick Install

Install a child proxy on any Linux machine, Raspberry Pi, or Android phone (Termux):

curl -fsSL https://www.financecheque.uk/fcukproxy/install.sh | bash

This installs:

  • child-proxy.mjs — OpenAI-compatible proxy agent on port 4001, registers with parent
  • agentos-gui — Next.js WebGUI on localhost:3000 (chat, terminal, pipeline view)
  • llama-server + MiniCPM-1B — local 1B-parameter LLM on port 8090
  • kiro-cli, kilo, hermes — AI coding and agent CLI tools
  • Whisper STT + Piper TTS — local speech-to-text and text-to-speech
  • pm2 — process manager with autostart on boot

After install, open: http://localhost:3000/chat

Architecture

The child proxy runs entirely on your local machine. It uses MiniCPM-1B via llama-server for fast, offline inference and falls back to the parent proxy (financecheque.uk) for cloud LLM access when needed. OpenClaw is a separate system and is not part of this stack.

🌐 Parent Proxy (financecheque.uk)

  • Cloudflare Worker — always-on, globally distributed
  • Routes queries to registered child proxies
  • Cloud LLM fallback (Groq, OpenRouter, Gemini, Mistral)
  • Never routes a request back to its origin child
  • Manages child registry, heartbeats, and job queue

💻 Child Proxy (this machine)

  • Runs locally — no public exposure required
  • WebGUI at localhost:3000
  • Local LLM at localhost:8090 (MiniCPM-1B)
  • Proxy agent at localhost:4001 (OpenAI-compatible)
  • Voice: Whisper STT + Piper TTS, push-to-talk in WebGUI
  • Agent tools: kiro-cli, kilo, hermes — all local-first

Agent CLI Tools

The installer configures three AI agent CLI tools that all route through the local proxy at localhost:4001:

kiro-cli

Kiro AI coding agent. Chat, file editing, code generation. Uses local MiniCPM-1B via child proxy. Run: kiro chat

kilo (kilocode)

Kilo coding assistant. Lightweight and fast. Configured to use local proxy at port 4001. Run: kilo

hermes

General-purpose agent. Memory, tool use, multi-turn tasks. Config: ~/.hermes/config.yaml — local-first, parent fallback. Run: hermes

All CLI tools (kiro, kilo, hermes) use localhost:4001/v1 as their LLM base URL. The child proxy routes them to MiniCPM-1B locally or escalates to the parent if needed.

Routing Policy

The proxy uses strict boolean logic to prevent infinite loops between parent and child:

Child Proxy receives a request:
  IF X-Forwarded: true  →  Use local LLM ONLY (came from parent — loop prevention)
  ELSE                  →  Forward to parent proxy at financecheque.uk
                            On timeout/failure: fall back to local LLM

Parent Proxy receives a request:
  IF X-Forwarded: true  →  Use cloud LLM ONLY (never route to children)
  IF X-Agentic: true    →  Route to designated agentic child
  IF X-Chat-Only: true  →  Respond via cloud LLM APIs directly
  ELSE                  →  Route to available child proxy
                            NEVER route back to the requesting child

Request Headers

HeaderDirectionMeaning

X-Chat-Only: trueChild → ParentChat query only, no agentic routing needed
X-Agentic: trueChild → ParentAgentic prompt — route to an agent-capable child
X-Source-MachineChild → ParentIdentifier of the originating child (loop prevention)
X-FCUK-TokenBothAuth token for child ↔ parent trust

OTA Updates

The child proxy checks for component updates automatically on startup and every 6 hours, fetching from the parent manifest at /api/proxy/ota/manifest. Updates apply without restarting active sessions.

# Check manually:
curl http://localhost:4001/ota/check

# Components updated via OTA:
#   child-proxy.mjs, agent.py, agent-exec.sh,
#   campaign-exec.sh, reflect.sh, skills/*
