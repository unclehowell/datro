Site procedures · Project and estate

PRINCE2 ledger of the programme: highlight reports, issue/risk logs, product status, lessons.

https://projects.bucklerfamily.estate/ · SOP 1.0.0

1 · Purpose and scope

PRINCE2 ledger of the programme: highlight reports, issue/risk logs, product status, lessons.

In scope: the pages and data files served at projects.bucklerfamily.estate. Out of scope: facts owned by another site (read them from their owner, below) and any other branch.

2 · Source of truth and data flow

This site owns: The PRINCE2 project office: PID, registers, highlight reports, asset register.

It reads: Every other site's status.

Inputs to read live before any write:

  • HubSpot deal 524565847259 (tasks, notes)
  • flywheel logs (this log.csv, reopen-loop results.tsv, research cycles)

Artifacts are linked from Wayback and open in the shared artifact viewer; no copy is kept on this site (single-source rule).

3 · Design system (frozen)

The current layout, navigation, colours, typography and the shared header are frozen. Any change to them is a class C change request approved by the executive. Pages start directly under the shared header; no repeated page titles.

4 · Content standard

As in the determinism standard and content rules: every factual sentence dated and sourced; record, the family's account and our case labelled; UNRESOLVED instead of a guess.

5 · Public-text rules

All rules in content and public text apply, checked against rules.json on the exact new bytes.

6 · Change control

Classes, template and commit rules: change control.

Must never change:

  • Figures only from named files or API reads.
  • Other agents' entries are not rewritten.
7 · Deploy and verify

Branch: projects
Route to live: datro@projects

Then verify live at 390 px and 1280 px as in deploy and verify.

8 · Routine checks and consistency
  • Newest highlight report date within 2 days of the last research cycle.
  • Daily site-flywheel scores line in the Benchmarks/Product Status page (append only, figures from this log.csv).
  • Build check passes.

Cross-site: settled values match the consistency ledger; artifact links point to Wayback; evidence citations resolve on Docs.

9 · Machine endpoints
EndpointWhat it returns
GET https://projects.bucklerfamily.estate/agent/tool/get_registersRead the PRINCE2 registers live as JSON tables: issue, risk, quality, product, lessons, daily log, work packages. Give register to read one; omit it for all.
GET https://projects.bucklerfamily.estate/agent/tool/get_highlight_reportRead the latest PRINCE2 highlight report (or one by id, e.g. hr-03) live: status, RAG, work packages, issues, risks and decisions.
GET https://projects.bucklerfamily.estate/agent/tool/get_pidRead the Project Initiation Documentation (the project's front page) live: project, stage, next gate, status and sections.
GET https://projects.bucklerfamily.estate/agent/tool/get_asset_registerThe Cedwyn Estate asset register (JSON).
https://projects.bucklerfamily.estate/estate/asset-register.jsonData file

Every site also serves /llms.txt, /.well-known/mcp.json, /agent/pages.json, /agent/search?q= and /agent/page?slug=. Reference: API, WebMCP.

10 · Issue and risk log

Kept in the Project Office registers in the handbook format, filtered to this site. Open UNRESOLVED points that touch this site are shown on its pages in the ledger's words.

11 · Handover

At the end of each session: branch head commit, live deployment, what changed, anything half done, the next three actions, and any other agent working on this branch. Filed with the highlight report.
